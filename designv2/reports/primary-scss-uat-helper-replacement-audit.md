# Primary SCSS vs UAT Helper Replacement Audit

Scope: non-`_abv2-*` primary SCSS files in `designv2/scss`. This focuses on the foundation/layout layer rather than the many component partials. No source files were changed.

## Files Reviewed

- `designv2/scss/base.scss`
- `designv2/scss/layout.scss`
- `designv2/scss/landing.scss`
- `designv2/scss/editorial.scss`
- `designv2/scss/buttons.scss`
- `designv2/scss/type.scss`
- `designv2/scss/_home-cta.scss`
- `designv2/scss/_test-buy-flow.scss`

## Short Answer

Most of these primary classes are still needed because they define v2 scope, rails, section rhythm, type roles and button contracts. The UAT CSS can replace some **mechanical layout behaviours** in markup, but it does not fully replace the primary v2 layer. The best candidates to reduce are generic primitives in `layout.scss`, simple image rules in `landing.scss`/`editorial.scss`, and basic flex centering inside `buttons.scss` if the button visual system later converges to `.si-btn`.

## Recommended Migration Position

### Safe to use UAT helpers instead of new v2 helper classes

- Use `.d-flex`, `.d-inline-flex`, `.align-items-center`, `.justify-content-center`, `.justify-content-between`, `.flex-column`, `.text-center`, `.w-100`, `.mx-auto`, `.img-fluid`/`.img-responsive` where the behaviour is purely mechanical and the HTML is under your control.
- Use `.container`, `.container-*`, `.container-medium`, `.choke-*` for ordinary rails where their exact widths are acceptable.

### Keep v2 primary classes

- Keep `.abv2-landing` and `.abv2-editorial` root scopes; they prevent platform CSS from leaking into the design surface.
- Keep `.abv2-wrap` / `.abv2-wrap--narrow` when the 36px gutter and v2 rail values are part of the design.
- Keep `.abv2-sec` and `.abv2-stack` for now because they encode semantic section rhythm; consider turning them into platform helpers later if adopted beyond v2.
- Keep `.abv2-btn` and `type.scss` until UAT exposes the final v2 SI button/type roles.

### Manual-review flags

- UAT utility classes often use `!important`, so moving from SCSS declarations to markup helpers can change cascade behaviour.
- `.container` in UAT carries Bootstrap gutter/max-width assumptions and may not match the ABV2 rails exactly.
- `.si-btn` and `.si-card` are component systems, not neutral helpers. They can reduce v2 CSS only if their whole visual contract is acceptable, not just because one declaration matches.
