# UAT Layout Helper Reuse Audit

Sources compared:

- UAT CSS: `designv2/incoming/abundanceuat-css.css`
- v2 SCSS: `designv2/scss`

Purpose: locate places where `designv2/scss` defines layout/helper-style behaviour that may already be available in the UAT/platform CSS. This pass includes both neutral utilities and component modifiers such as `.si-card--0`. No source partials were changed.

## Executive Summary

- Parsed 2756 UAT classes with relevant declarations and 761 v2 selector blocks with at least one declaration match.
- This audit now catches **component helper/modifier matches** as well as neutral utilities, so examples like `.si-card--0 { padding:0 }` are surfaced explicitly.
- Strongest neutral reuse candidates remain simple display/flex/alignment/text/width helpers. Strongest component reuse candidates are `.si-card*`, `.si-table*`, and button system classes where the visual contract is acceptable.
- Bespoke v2 grids, rails, masks, artwork positioning and component-specific responsive behaviour should generally remain component-owned.

## How To Use This Report

- For neutral helper matches, the likely migration is a template/markup change, for example adding `.d-flex .align-items-center` rather than keeping a bespoke v2 class whose only job is alignment.
- For component helper matches, compare the whole component contract, not just the matching declaration. For example `.si-card--0` removes padding, but `.si-card` also brings background, border, radius, shadow, flex column and overflow.
- Keep v2 SCSS where the rule defines component semantics, exact v2 rail widths, responsive grid collapse, masks, decoration, or child-specific positioning.
- Treat `.si-card__inner` as still missing from UAT CSS based on the earlier audit, so card internals may still require a v2 layer even when `.si-card si-card--0` covers the shell.

## Manual Review Flags

- Exact declaration matches are opportunities, not automatic replacements. Cascade, specificity and markup ownership still need review.
- Some UAT helpers may come from Bootstrap and include breakpoint assumptions or `!important`; verify before relying on them inside v2 components.
- Experiment partials were scanned but omitted from the main tables to keep the report focused.
