GOAL
Split a large monolithic CSS file into component-level SCSS files, preserving rule order and source provenance, without changing behaviour.

CONTEXT

* This is part of a design system (abv2).
* CSS is currently a large monolith containing multiple components and overrides. These are spread across 4 files in designv2/incoming
* We are preparing to move to a Sass-based component architecture.
* The CSS contains duplicate/overlapping rules from different source files (homepage, council pages, editorial).
* At this stage we are NOT cleaning or deduplicating — only restructuring safely.

TASK

1. Identify component groupings based on class prefixes (e.g. `.abv2-open-card`, `.abv2-council-hero`, `.abv2-council-live`, etc).
2. Split the CSS into separate SCSS component files.
3. Each component file should contain ALL rules related to that component, including responsive rules.
4. Preserve the ORIGINAL ORDER of rules exactly as they appear in the source file.
5. If the same component appears multiple times (from different source sections), KEEP BOTH — do not merge or deduplicate.

PROVENANCE REQUIREMENT

* For each component file, group rules by their original source location.
* Add a comment block BEFORE each group indicating source origin.

FORMAT:

/* =========================================================
SOURCE: <source file or section name>
========================================================= */

<rules from that source>

* Do NOT add inline comments per selector.
* Do NOT annotate every line.
* Only use block-level source grouping.

CONSTRAINTS

* Do NOT change any CSS values
* Do NOT combine or simplify rules
* Do NOT rename classes
* Do NOT introduce new abstractions
* Do NOT convert to mixins or variables yet
* Do NOT reorder anything

OUTPUT FORMAT

* Output as multiple SCSS files into git folder /designv2/scss
* One file per component
* Use naming convention: _abv2-[component].scss
  Example: _abv2-open-card.scss

OPTIONAL

* At top of each file include:

/* ========================================
COMPONENT: <name>
Status: unrefined (contains duplicates)
======================================== */

SUCCESS CRITERIA

* No behaviour changes
* No lost rules
* Clear separation by component
* Clear visibility of which rules came from which source
* Ready for manual “winner selection” pass afterwards
