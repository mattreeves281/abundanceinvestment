ABV2 Sass variable gaps
=======================

Source checked:
designv2/config/_config abundance revised.scss

Purpose:
These are the extra Sass variables or aliases needed if the current ABV2
runtime CSS-token layer is moved into the platform Sass build.

Do not duplicate existing platform values where an exact variable already
exists. Use existing variables directly for:
- $pure-white / $abundance-neutral-000
- $abundance-neutral-200 / 300 / 400 / 800 / 900
- $abundance-pink / $abundance-pink-light / $abundance-pink-surface
- $abundance-cyan / $abundance-cyan-light / $abundance-cyan-surface
- $abundance-yellow / $abundance-yellow-light / $abundance-yellow-surface
- $abundance-green
- $abundance-blue
- $spacer-3xs / 2xs / xs / sm / lg
- $si-font-primary / secondary / tertiary

Implementation note
-------------------

For Sass-native component files, prefer existing platform variables first:
- $spacer-3xs for 8px
- $spacer-2xs for 16px
- $spacer-xs for 24px
- $spacer-sm for 32px
- $spacer-lg for 64px
- $si-font-primary for body sans
- $si-font-secondary for serif headings
- $si-font-tertiary for UI/button/table header text

Only use the ABV2 additions above where the component requires an exact
in-between value or a reusable alpha/semantic alias that the platform does not
currently expose.
